# 2026-09-18

## StarYunFan 个人网站：现状分析与改造方案

对项目做了完整走查（Vue3 + Vite + Tailwind v4 + markdown-it，49 篇 Obsidian 笔记构建期生成 noteManifest，运行时 fetch 原文）。

**结论要点**
- 保留：首页（简化动效）。改造：笔记页 → 时间线归档、关于页 → 简历式。删除：任务页（纯前端无后端 + 假数据重复）、天气卡片（第三方接口不可靠）。新增：时间线、项目、开源热力。
- 样式方向：保留毛玻璃但降级为层次提示（透明度 0.08 / blur 20px / 去掉 saturate），去掉渐变裁剪文字、大投影、阶梯延迟动画、emoji 图标；统一圆角 12px、单一强调色、字重只用 400/600。
- MD 时间线前提：当前 `date: new Date()` 是假数据，需在 `scripts/generate-notes-manifest.mjs` 用 fs.statSync().mtime 或 frontmatter 写入真实日期。

**发现的既有问题（待修）**
- `notes/index.vue` 用了 `prose-*` 类但未安装 `@tailwindcss/typography`，排版类不生效。
- `tailwind.config.ts` 是 v3 写法，v4（@tailwindcss/vite）下不会被加载，属于死配置。
- `App.vue` 的 localStorage/sessionStorage 清空逻辑是死代码（`isRefresh` 恒为 true）。
- 死代码：echarts 依赖未使用、SeigaCard.vue 未使用、control.css 的 .seiga-card 白底与全局风格冲突。
- axios 仅为天气一个 GET 而引入；highlight.js 全量引入体积过大；`view/Stasks` 命名异常。
- 路由为 hash 模式 + base `/StarYunFanSite/`。

**GitHub 绿墙结论**：贡献日历只有 GraphQL 且必须带 token，浏览器直连会泄露。方案为 Actions 构建期用 PAT 拉取生成 `public/data/contributions.json`，前端 fetch 静态文件 + cron 定时刷新。

用户定位：该项目保持纯前端，不要引入后端。

**pnpm 注意事项（踩坑）**：本环境下 `pnpm install` 会被沙箱的 safe-delete 批量删除保护中断，且**中断时 node_modules 已被清空**。恢复方式：`CI=true pnpm install --offline`（约 1 分钟）。改完 package.json 后建议先 `CI=true pnpm install --lockfile-only` 更新 lockfile，再完整 install 一次，之后 `pnpm run build` 的自动依赖检查才不会反复触发重装。安装过程会在项目根留下 `_tmp_*` 空文件，记得清理。
