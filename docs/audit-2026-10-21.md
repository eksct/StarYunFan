**F01：BOM 绕过草稿过滤**

位置：`src/utils/noteData.mjs:4`、`scripts/lib/generate-notes.mjs:62`、`src/content/siteConfig.mjs:27`。

复现：文件内容为 `\ufeff---\ndraft: true\n---\n正文`，其中 `\ufeff` 为真实 UTF-8 BOM。`parseFrontmatter()` 返回空元数据，`isPublishedNote()` 返回 `true`。在独立临时笔记库执行真实 `generateNotes()`，`major/A/draft.md` 进入元数据并生成文章 JSON。

预期：BOM 不应改变 frontmatter 的发布语义。建议在解析入口去除单个开头 BOM，并覆盖真实生成流程中的草稿及草稿附件排除。当前公开笔记逐篇检查：76 篇，BOM 为 0；此结论不代表未发布目录中永远不会出现该格式。

**F02：手机页面横向溢出**

复现：Chrome，视口 `320 × 844`，线上逐篇打开 76 个站内阅读页并测量 `document.documentElement.scrollWidth - innerWidth`。

针对性 DOM Range 检查确认：`ParameterNameDiscoverer`、`SpelExpressionParser` 的页面 H1 超出视口；MVC05 的下一篇标题 `ParameterNameDiscoverer` 超出视口。应允许长单词折行并约束相邻文章布局。76 个独立文章页在同样视口下没有页面级横向溢出。

**F03：本地预览中的编码路径不兼容**

位置：`src/content/siteConfig.mjs:9`、`src/utils/notes.ts:214` 与 Vite preview 静态文件处理的组合。

复现：生产构建后启动 `pnpm preview`，打开 `@Around` 等注解笔记。请求 `.../%40Around.md.json` 返回 `200 text/html`，正文实际为应用 `index.html`，`response.json()` 失败；同一请求把 `%40` 换成字面 `@` 后返回正确 JSON。`安装&连接` 的 `%26` 也复现。

受影响的 12 篇：`@Around`、`@Aspect`、`@ConditionalOnMissingBean`、`@ConditionalOnProperty`、`@Data`、`@Getter and @Setter`、`@NonNull`、`@RequiredArgsConstructor`、`@Slf4j`、`@UtilityClass`、`@Val And @Var`、`安装&连接`。

线上逐篇验证的 76 个文章 JSON 均可解析，并具有字符串 `html`、数组 `toc`。所以这项属于已确认的本地预览兼容问题，不能据此报告线上文章加载失败。修复时应同时验证开发服务器和生产预览，保留路径编码的正确性。

**F04：首个 H1 被错误删除**

位置：`scripts/lib/render-note.mjs:78` 附近。

现有 `public/postDir/major/编程语言/JAVA/依赖/Lombok/注解/@Val And @Var.md` 先写 `# @val`，后写 `# @var`。渲染器把前者改成空 span，把后者降为 H2；线上正文可见标题仅有 `@var`。首个标题是章节名称，不能视作文件名标题的重复。建议只有确认与页面标题相同的标题才去重，其余 H1 降级并保留内容和锚点。

**F05：URL 解析边界**

位置：`scripts/lib/render-note.mjs:28`、`:113`、`:133`、`:154`。

以下用临时文章直接调用生产渲染器，均已复现：

| 输入 | 实际结果 | 预期 |
| --- | --- | --- |
| `[README](https://example.com/README.md)` | 当作内部笔记，产生无法解析的诊断，生成流程据此终止 | 保留外部链接 |
| `[target](target.md?view=1)` | 不转换、不校验，原样输出相对 `.md` URL | 识别笔记路径及查询部分；不要输出指向未发布原始 Markdown 的链接 |
| 指向 `C#.md` 的 `[C sharp](C%23.md)` | 过早解码后把文件名里的 `#` 当成片段分隔符 | 在拆分 URL 结构后解码路径 |
| 指向 `100%20.md` 的 `[Percent](100%2520.md)` | 重复解码后找不到真实文件 | 路径只按其编码层级解码 |
| `![pic](//example.com/pic.png)` | 协议相对 URL 被当成本地图片，产生缺图诊断 | 按外部图片处理 |

这些属于 URL 结构识别问题，合并为一项整改，避免拆成多个重复任务。当前文章产物没有因此构建失败。

**F06：普通附件链接静默失效**

位置：`scripts/lib/render-note.mjs:154`、`scripts/lib/generate-notes.mjs:56`、`:72`。

复现：同目录确实存在 `pic.png`，正文写 `[download](pic.png)`。渲染结果 `href="pic.png"`、`assets: []`、`diagnostics: []`。独立文章位于 `notes/.../note.md.html`，图片应位于发布附件目录，原地址解析错误；只以链接形式引用时附件还不会被复制。现有产物校验也不检查这一类链接。

应至少正确处理已经支持的本地图片链接；对于不支持的附件类型应明确诊断。此问题不意味着必须新增 PDF 下载系统或放宽整个笔记库的发布白名单。

**F07：锚点碰撞**

位置：`scripts/lib/render-note.mjs:74`、`:94`。

复现一：`## Same\n## Same\n## Same-1` 生成 `same`、`same-1`、`same-1`。复现二：`## block-item\n\nParagraph ^item` 生成两个 `block-item`。

渲染器不报告诊断；`scripts/verify-dist.mjs` 的重复 ID 检查会拦住这类产物。应对整篇文章的标题、块引用和页面保留 ID 统一分配唯一 ID，保留可预测的引用关系。现有 76 篇文章的 ID 校验通过。

**F08：SVG 与尺寸校验冲突**

位置：`scripts/lib/generate-notes.mjs:56`、`:80`、`:85`；`scripts/verify-dist.mjs:29` 附近。

复现：临时笔记引用具有 `width="20" height="10"` 的本地 SVG。生成器接受并复制图片，但只对 PNG/JPEG/WebP/GIF 读取尺寸，最终 img 没有 width/height。现有产物校验要求每张本地图片都声明尺寸，因此这条发布路径不一致。

应为 SVG 生成适当尺寸，或针对具有 viewBox 等不同 SVG 情况明确布局及校验规则。当前公开文章引用的 2 个附件未触发这项问题。

**F09：空 frontmatter**

位置：`src/utils/noteData.mjs:4`。

复现：`parseFrontmatter('---\n---\nBody')` 抛出“Frontmatter 缺少结束分隔线”，虽然结束分隔线存在。原因是正则要求内容与结束分隔线之间额外出现换行。预期返回空元数据和 `Body`；非空元数据的既有校验继续有效。

**F10：图片预览滚动背景**

位置：`src/view/notes/NoteReader.vue:218`、`:226`。

复现：手机视口打开《11 网络编程》的图片预览，在遮罩区域滚轮下移 650px。背景 `scrollY` 从 0 变为 549；关闭预览时文章位置已改变。应在打开期间锁定背景滚动，关闭及卸载时恢复。Escape 和关闭后的焦点返回目前正常。

**F11：失败图片仍可打开空预览**

位置：`src/view/notes/NoteReader.vue:218`、`:242`、`:265` 附近。

复现：浏览器拦截并拒绝文章图片请求。图片 `complete=true`、`naturalWidth=0`，仍带 `role="button"` 和 `tabindex="0"`；聚焦后按 Enter 会创建图片预览对话框。应提供失败反馈并禁用无效预览。当前线上附件 HTTP 检查没有发现图片失效，此项通过故障注入验证。

**F12：取消复制后仍报成功**

位置：`src/Component/SeigaNav.vue:193`、`:265` 附近。

复现：让 `navigator.clipboard.writeText()` 拒绝，在弹出的手动复制 prompt 里选择取消；分享按钮仍显示“已复制”，播报“链接已复制”。RSS 复制使用相同的无条件成功分支。应只在能够确认写入剪贴板成功时报告成功，手动复制提示不能视为已完成复制。
